상태: 초안 (2026-11-23, Phase 1 후반 구현 반영 2026-11-24, Phase 4 공간·신고·관리자·정책 화면 반영 2026-11-25, Phase 5 색 대비 계산값·접근성 규칙 2026-11-25)

기준 자료: `hanpan_v3_design_spec.md`, `hanpan_v3_design_lab.html`(`/* HANPAN V3 */` 이후 CSS가 최종값), `hanpan_v3_claude_prompt.md`. 충돌 시 v3 시안을 우선하고, 의도적으로 바꾼 부분은 §3.3에 적는다.

## 1. 원칙

- 잉크 블랙 단일 테마. 주황·그라데이션·장식 카드·과한 그림자·가짜 통계 금지. Design Lab 상단 바와 테마·폰트 토글은 넣지 않는다.
- Primary CTA(검은 버튼)는 화면의 주요 결정 지점 1곳에만. 목록 행에는 버튼을 넣지 않고 행 전체를 상세 링크로 만든다.
- 색만으로 상태를 전달하지 않는다. 항상 텍스트를 함께 쓴다.
- 상세와 생성·수정 화면은 같은 타이포·버튼·입력 컴포넌트를 쓴다.
- 모임 사진은 없다(업로드 미구현). 장르별 중립 SVG 플레이스홀더를 쓰고 AI 생성 이미지나 출처 불명 이미지를 쓰지 않는다.

구현 메모(Phase 1 후반):

- 상세 모바일 하단 CTA 바는 단일 DOM 요소다(모바일 `fixed`, 데스크톱 우측 패널 안 `static`). 바가 떠 있는 동안 하단 내비를 숨기고, 바 높이를 `--bottom-nav-offset`에 써서 본문 하단 여백·토스트 위치가 바를 피한다(`src/components/layout/mobileBottomBar.ts`).
- 비활성 CTA·승인 버튼은 `aria-disabled="true"`(포커스 유지) + 사유 문구 `aria-describedby`로 구현했다(`Button`의 `focusableWhenDisabled`).
- 위험 동작 버튼은 `Button variant="danger"`(흰 배경 + 테두리 + 위험 글자색)로 통일했다.

추가 제안(확정 필요):

- A. 시안 기본 CSS에 남은 저대비 회색(안내 `#868686`, 푸터 `#96989a`, 개수 `#9a9a9a`, eyebrow `#757D85` 약 4.2:1)은 `muted`로 통일한다.
- B. `border`(약 1.2:1)만으로 입력란 경계를 표시하면 WCAG 1.4.11(비텍스트 대비 3:1)에 못 미칠 수 있다. 입력란에만 진한 테두리 토큰(예: `#8B949E`, 계산상 약 3.1:1)을 쓸지 결정 필요.
- C. iOS Safari는 16px 미만 입력란에 포커스하면 화면을 확대한다. 모바일 입력 글자를 16px로 올릴지 결정 필요.
- D. 목록 행은 시안의 `article role="button"` 대신 `<a href="/meetings/:id">`로 만든다(새 탭·링크 복사 가능). 썸네일은 장식이므로 `alt=""`.
- E. 헤더 메뉴명은 시안의 "공간 찾기"를 따른다(마스터 프롬프트의 "공간 정보"와 다름).

## 4. 화면별 구성

### 4.1 탐색 (`/`, `/meetings`)

- 순서(모바일): 헤더 → (개발 띠) → 히어로·빠른 이동(`/`만) → "날짜 선택" + 날짜 스트립 → 장르 칩(전체 + 6종) → "곧 열리는 모임." + 개수 → 검색 → [모집 중만] [정렬] → 목록 → "더 보기"(Secondary, 전체 폭) → 안내 카드 2개(`/`만) → 푸터 → 하단 내비.
- 데스크톱: "날짜로 찾기" 라벨(164px) + 스트립, "게임 유형" 라벨 + 칩 + 모집 중만 + 정렬, 제목 행 오른쪽에 검색.
- 히어로 문구(시안 유지): eyebrow "DAEJEON BOARDGAME CLUB", 제목 "이번 주, 같이 한 판.", 설명 "대전에서 보드게임 할 사람, 지금 바로 만나보세요."
- 지역 선택: 헤더 버튼 "대전 · 전체 지역" → 다이얼로그에 전체 + 권역 6개(2열 칩) → `region` 쿼리 변경. 탐색 화면이 아니면 탐색으로 이동하며 적용.
- 목록 행: 1줄 [장르] 게임명 · 진행 수준 / 2줄 제목(2줄 말줄임) / 일시 "11.28 (토) 19:00"(올해가 아니면 연도 포함) / 장소 "둔산·탄방 · 공간명 또는 장소 메모 또는 장소 미정" / 인원 "5/8명" + "3자리 남음"(최소 인원 미달이면 "· 최소 4명") 또는 배지.
- 개수는 필터 결과 전체 건수. 필터·검색 변경은 URL에 즉시 반영하고(`replace`), 날짜·장르 선택은 히스토리에 쌓지 않는다.
- 안내 카드: "함께할 사람을 찾고 있나요?"(→ 모임 만들기), "게임할 공간도 한눈에."(설명: "대전의 보드게임 카페와 파티룸 정보를 확인할 수 있어요. 예약은 각 공간의 공식 채널에서 해 주세요." → 공간 찾기).

### 4.2 모임 상세 (`/meetings/:id`)

- 본문: 뒤로가기 → [장르] · 진행 수준 → 제목 → 정보 목록(일시 "2026년 11월 28일 (토) 19:00~22:00 · 약 3시간", 장소, 게임명, 진행 수준, 승인 방식 "신청 즉시 확정" / "모임장 확인 후 확정", 모임장 닉네임) → 소개 → 유의사항 → 공간 정보(공개 공간이면 상세 링크, 확인된 예약 링크가 있을 때만 외부 링크) → 공유 · 신고(텍스트 버튼).
- 사진이 없으면(현재 항상) 큰 배너를 두지 않는다(무의미한 대형 배너 금지). 목록 썸네일과 같은 비율의 작은 장르 플레이스홀더를 데스크톱은 제목 블록 왼쪽(183×105), 모바일은 장르 배지 위(86×96)에 둔다. 장르가 글로 함께 보이므로 장식(`aria-hidden`)이다. 사진을 도입하면 사진만 본문 위 배너로 보여준다.
- 모임장 계정이 삭제된 모임(`hostId` null)은 모임장 행에 "탈퇴한 사용자"로 보이고, CTA는 "모집 마감" + "모임장이 탈퇴해 신청을 받지 않아요."
- 인원 블록: "현재 참여 인원 5/8명", 최소 인원, 대기 인원 수. 참가자 닉네임은 보여주지 않는다.
- 소개·유의사항은 일반 텍스트(줄바꿈 유지)로만 렌더링한다. URL 자동 링크·HTML 해석 없음.
- 공유: Web Share API가 있으면 사용, 없으면 주소 복사 후 토스트 "링크를 복사했어요".
- 신고: 로그인 필요. 다이얼로그(사유 7종 라디오, 본문 1000자, "신고는 운영자가 직접 검토해요. 신고만으로 자동 제재되지 않아요.").

### 4.3 모임 생성·수정 (`/meetings/new`, `/meetings/:id/edit`)

- 기본 노출: 게임 장르(라디오 칩) · 게임명(선택, 40자) · 제목(2~60자, 글자 수) · 날짜(`input type=date`, KST 오늘~90일) · 시작 시간(30분 단위 Select) · 예상 소요(30분 단위, 30분~12시간) · 권역 · 장소 메모(선택 60자, 비우면 '장소 미정') · 정원(도움말 "모임장을 포함한 전체 인원이에요") · 진행 수준 · 참가 승인 방식 · 소개(2000자).
- 고급 설정('추가 설정', 접힘, `aria-expanded`): 최소 인원(모임장 포함, "이 인원이 모이지 않아도 모임이 자동으로 취소되지는 않아요."), 대기 신청 허용(기본 켜짐, "자리가 나면 모임장이 직접 확정해요. 자동으로 확정되지 않아요."), 유의사항(1000자). 첫 오류가 접힌 영역이면 펼친 뒤 포커스한다.
- 공간 선택(Phase 4): 권역 아래 "공간 (선택)" Select — 권역을 고르기 전에는 비활성("권역을 먼저 고르면…"), 고르면 그 권역의 공개 공간만 선택지(기본 "장소 미정"). 고른 공간의 유형·주소를 도움말로 보여준다. 권역을 바꾸면 그 권역에 없는 공간 선택은 풀린다. 검증(서버 `_meeting_input`과 같은 규칙, `validateVenueSelection`): 새로 고르거나 바꾼 공간은 공개 목록에 있어야 하고 권역이 같아야 한다. 수정 화면에서 비공개로 바뀐 원래 공간은 "(현재 연결된 공간)"으로 그대로 둘 수 있다(권역은 같아야 함). 공간 목록을 불러오지 못하면 "장소 미정 + 장소 메모"만 쓰도록 안내한다.
- 비활성 카테고리(관리자가 끈 것)는 새로 고를 수 없다. 수정 중인 모임의 기존 카테고리는 남긴다.
- 게임 연결 보존: 관리자가 등록한 게임(`gameId`)에 연결된 모임을 수정할 때 게임명 입력을 그대로 두면 연결을 유지하고, 바꾸거나 비우면 직접 입력 이름으로 저장한다.
- 날짜·시간은 KST 벽시계 시각으로 해석해 UTC ISO로 보낸다(`kstDateTimeToIso`). 검증 규칙은 `src/domain/meetingSchema.ts`(Zod, 서버와 같은 한도 `src/domain/limits.ts`).
- 홀덤(비금전) 선택 시: 안내 상자 + 필수 체크 "베팅·환전·상금·경품이 없는 비금전 모임으로 진행해요".
- 제출: Primary "모임 만들기" / "수정 내용 저장". 오류는 필드 아래 + 첫 오류 필드로 포커스. 서버 오류 `detail`의 필드명을 해당 입력에 매핑.
- 수정 화면 상단 안내: "일정이나 장소를 바꿔도 참가자에게 자동 알림이 가지 않아요. 참가자는 모임 상세에서 바뀐 내용을 확인해요."
- 정원 줄이기 제한 도움말: "현재 확정 인원 N명보다 적게 줄일 수 없어요."
- 수정 불가(취소·시작·종료): 폼 대신 "이 모임은 더 이상 수정할 수 없어요" + 상세로 가기.

### 4.4 내 모임 (`/my/meetings`)

- 상단 전환: "참가한 모임" / "내가 연 모임"(`role=applied|hosted`). 탭: 예정·대기·완료·취소(`tab=upcoming|waiting|done|cancelled`).

| 탭 | 참가한 모임 | 내가 연 모임 |
|---|---|---|
| 예정 | `confirmed` + 종료 전(진행 중 포함) | 취소 전·종료 전 |
| 대기 | `pending`, `waitlisted` + 시작 전 | 승인 대기 신청이 있는 예정 모임 |
| 완료 | `confirmed` + 종료됨(출석 표시) | 종료됨 |
| 취소 | `cancelled`, `rejected`, `meeting_cancelled`, 시작 때까지 확정되지 않은 신청 | 취소됨 |

- 행: 탐색 목록 행(`MeetingRow`) 재사용 + 내 상태 배지(문구 병기) — 행 전체가 상세 링크, 내가 연 모임은 행 아래 별도 "참가자 관리" 링크(링크 중첩 금지). 숨김 처리되어 모임을 읽을 수 없는 행은 "모임 정보를 볼 수 없어요 / 운영 정책에 따라 비공개 처리된 모임일 수 있어요"로 표시하고, 신청 상태만으로 분류한다(활성 신청 → 예정·대기, 그 외 → 취소).
- 구현: 상단 전환은 `role=tablist`(←/→/Home/End, roving tabindex), 상태는 `aria-pressed` 칩(개수 표시). 내가 연 모임은 '예정'과 '대기'에 함께 나올 수 있다. 정렬: 예정·대기는 가까운 순, 완료·취소는 최근 순.

### 4.5 참가자 관리 (`/meetings/:id/participants`)

- 상단: 제목·일시, "확정 5/8명 · 승인 대기 2명 · 대기 1명", "모집 마감하기"/"모집 다시 열기"(Secondary), "수정" 링크.
- 구역: 승인 대기 → 대기자("자리가 나면 직접 승인해 주세요") → 확정(모임장 맨 위, "모임장" 표시) → 지난 신청(거절·취소, 접힘). 행: 닉네임, 신청 시각, 남긴 말, 상태.
- 승인·거절은 행마다 Secondary 버튼(검은 버튼 반복 금지). 거절은 확인 다이얼로그("거절하면 이 모임에 다시 신청할 수 없어요").
- 출석 체크: 시작 후~종료 7일 이내, 확정 게스트에게 [참석] [불참] 토글(`aria-pressed`).
- 모임 취소: 하단 위험 동작 → 다이얼로그(사유 선택 입력 200자, "참가자 신청은 모두 '모임 취소' 상태로 바뀌고 참가자는 내 모임에서 확인할 수 있어요. 이메일·푸시 알림은 보내지 않아요.").
- 모임장이 아니면 권한 없음 화면(참가자 목록은 요청하지 않는다).
- 구현: 자리가 없으면 승인 버튼은 `aria-disabled` + "남은 자리가 없어 승인할 수 없어요…" 사유. 출석 토글은 칩(`aria-pressed`, 다시 누르면 미확인으로). 시작 이후에는 승인·거절·마감·수정·취소 동작을 숨긴다. 동작 실패는 상단 `role="alert"` 문구, 성공은 토스트. "모임 수정" 링크는 상단 동작 줄에 둔다.

### 4.6 로그인·프로필 (`/login`, `/auth/callback`, `/profile`)

- `/login`: "참가 신청과 모임 만들기는 로그인 후 이용할 수 있어요." Google 버튼, Kakao 버튼(플래그 켜진 경우만), mock 모드에서만 "개발용 테스트 계정 선택" 목록. 서비스 설정 전이면 "지금은 로그인을 사용할 수 없어요". `미확인:` Google·Kakao 로그인 버튼 브랜드 가이드(카카오 노란색 버튼 등) 준수 범위.
- `/auth/callback`: "로그인 중이에요…" → 성공 시 복귀, 실패 시 "로그인을 완료하지 못했어요" + 다시 시도.
- 최초 설정(`/profile`, 약관 동의 전): 닉네임(임시값이 미리 채워짐) · 선호 권역(선택) · 관심 장르(선택, 최대 6) · 필수 동의 2개(이용약관, 개인정보 수집·이용 — 정책 페이지 링크) → "시작하기". `미확인:` 만 14세 이상 확인 항목 추가 여부.
- 일반 프로필: 닉네임·권역·소개·관심 장르 수정, 로그아웃(Secondary), "탈퇴 요청"(위험 동작) → 다이얼로그(미래 신청·주최 모임 취소, 닉네임 비식별화, 계정 삭제는 운영자가 처리, 보관 항목은 개인정보처리방침 링크, 확인 체크) → 요청 후 로그아웃하고 `/account/deletion-requested` "탈퇴 요청이 접수됐어요" 화면.
- 미구현: "로그인 방식 표시(본인에게만)" — 세션 계약(`SessionUser`)에 공급자 정보가 없다. Supabase 어댑터 연결 때 추가 검토.
- mock 모드 로그인: Google 버튼을 누르면 오류 대신 "개발 모드에서는 … 테스트 계정 중 하나로 로그인해 주세요" 안내와 함께 테스트 계정 섹션으로 포커스를 옮긴다. 섹션에는 계정 4개(일반 2·최초 설정 전 1·관리자 1)와 "개발 데이터 초기화"가 있다. 상태는 `localStorage` `hanpan.mock.v2`에 저장된다(Phase 4에서 공간·신고·카테고리가 추가돼 v1 값은 버리고 새로 만든다. 24시간이 지나면 예시 데이터를 새로 만든다).
- 헤더: 로그인하면 "로그인" 대신 닉네임 첫 글자 원(32px, 터치 44px)이 `/profile` 링크가 된다. 하단 내비 "마이"는 비로그인 시 `/login`.
- 이용 제한·탈퇴 요청 계정은 헤더 위에 안내 띠를 보여준다.

### 4.7 공간 (`/venues`, `/venues/:id`) — Phase 4 구현

### 4.8 관리자 (`/admin`) — Phase 4 구현

- 접근: 라우트 가드(로그인 + 최초 설정) → 화면에서 `SessionUser.isAdmin` 확인. 아니면 "접근 권한이 없어요." + "관리자 도구는 운영자 계정만 쓸 수 있어요."(관리자 데이터 요청 안 함). 비로그인은 returnTo 저장 후 로그인. **화면 확인은 사용성용이며 권한의 경계는 서버(RPC의 `is_admin()`·RLS)** 다. 헤더·하단 내비에는 노출하지 않고, 관리자에게만 프로필 화면에 "관리자 도구" 섹션 + "관리자 도구 열기" 링크.
- 상단: PageTitle "관리자 도구" + "모든 변경은 서버에서 권한을 다시 확인하고 감사 기록에 남아요." 탭(기존 `Tabs`, ←/→/Home/End): 신고 · 모임 · 사용자 · 공간 · 카테고리 — URL `?tab=meetings|users|venues|categories`(기본 신고). 좁은 화면은 탭 줄만 가로 스크롤.
- 신고: 상태 칩(접수·검토 중·처리 완료·기각·전체, 기본 접수) + "신고만으로 자동 제재하지 않아요…" 안내 → 항목: 상태·대상 유형 배지, 사유, "숨김 중인 모임" 배지, 대상(모임 → 상세 링크 / 사용자 → 닉네임, 삭제됐으면 "삭제된 모임/사용자"), 본문(없으면 "상세 내용 없음"), 접수 시각·신고자 닉네임·처리 시각 → 처리 상태 Select + 관리자 메모(1000자, "신고자에게 보이지 않아요") + "처리 상태 저장"(바뀐 것이 있을 때만). 20개씩 이전/다음.
- 모임: 제목·게임명 검색 + "숨김만 보기" 칩 → 행: 숨김·진행 상태·장르 배지, 제목(상세 링크), 일시·모임장·확정 인원, 숨김 사유 → "숨기기"(확인 대화상자, 사유 필수 200자 — 사유가 비면 확인 버튼 비활성) / "숨김 해제"(확인) / "모임 취소"(위험, 확인, 사유 선택 200자 — 취소·종료된 모임에는 없음).
- 사용자: 안내 "이용 제한은 영구 제재가 아니며 이의제기를 검토해요. …" → 닉네임 또는 id 검색(빈 검색어면 최근 가입 20명, 이메일 없음) → 행: 닉네임·상태 배지·가입일·최근 30일 신고 수 → "이용 제한"(위험)/"제한 해제" 확인 대화상자(처리 메모 200자, 감사 기록에 남음). 본인("내 계정은 바꿀 수 없어요")·탈퇴 요청 계정("탈퇴 요청 계정은 바꿀 수 없어요")은 버튼 없음.
- 공간: 등록 기준 안내 → "새 공간 등록" → 인라인 폼(공간 이름 60자·권역·주소 200자·유형 칩·공식 홈페이지·공식 예약 페이지(https만)·소개 1000자·정보 확인일(날짜, 오늘 이하 — KST 00:00으로 저장)·공개 체크) → 행: 공개/비공개·유형 배지, 이름(공개면 상세 링크), 권역·주소·정보 확인일, "수정" / "공개로 전환"·"비공개로 전환"(확인 대화상자, 삭제 대신). 서버 오류 detail은 해당 입력에 연결.
- 카테고리: 안내(비활성은 새 모임에서 못 고름, 기존 모임 유지, 이름·순서 변경 미지원) → 행: 이름·활성 배지·id·순서·설명 → "비활성화"/"활성화"(확인 대화상자). 이름·설명·순서 바꾸기는 MVP 화면에서 제외(SQL Editor + 프론트 상수 함께 배포 — OPERATIONS §6).
- 실패 문구(`adminErrorMessage`): NOT_FOUND "대상을 찾을 수 없어요. 새로고침해 주세요.", NOT_ADMIN/권한 오류 "관리자 권한이 없어요…", 종료된 모임 취소 "이미 끝난 모임은 취소할 수 없어요.", 사유·메모 길이·본인·탈퇴 계정 등 detail별 문구.

### 4.9 정책·404 — Phase 4 구현

- `/policies/:slug`(`terms`·`privacy`·`operations`): 문서 전환 내비(이용약관·개인정보처리방침·운영정책) → PageTitle(이용약관(초안)·개인정보처리방침(초안)·운영정책(초안)) + 한 줄 설명 → 경고 Notice "초안 / 운영자·법률 검토 전 초안이에요. 정식 공개 전에 바뀔 수 있어요." → 본문.
- 본문은 `src/content/policies/*.md`(원본 초안 `docs/policies/*.md`·`docs/OPERATIONS.md`의 이용자 대상 부분을 옮긴 것)를 Vite `?raw`로 읽어 의존성 없는 마크다운 부분집합 렌더러(`src/lib/markdown.ts` + `src/components/content/Markdown.tsx`)로 그린다: 제목·문단·목록·인용·표·구분선·굵게·코드·내부 링크만, HTML 해석 없음(문자열 그대로), React 요소만.
- 정해지지 않은 값(운영 이메일·운영자 정보·시행일·개인정보 보호책임자)은 "**확정 전**"으로 쓰고 가짜 값을 넣지 않는다. 법률 검토가 필요한 항목은 "검토 중이에요"로 쓴다.
- 그 외 slug와 없는 경로는 404 "페이지를 찾을 수 없어요" + 홈으로.

### 4.10 오류 경계

- 라우트 오류(`RouteErrorPage`): 렌더 오류·청크 로딩 실패·화면이 처리하지 못한 데이터 계층 오류를 "화면을 불러오지 못했어요." + 코드별 문구(연결 불안정·서비스 준비 중 등, `getUnexpectedErrorDescription`) + 새로고침.
- 앱 전역(`AppErrorBoundary`, 라우터 바깥): 인증·토스트 컨텍스트 등에서 터진 오류를 "화면을 표시하지 못했어요." + 같은 문구 + 새로고침·홈으로(일반 링크). 오류 원문·스택은 화면에 쓰지 않고 개발 모드 콘솔에만.

| 서비스 설정 전(unconfigured) | "서비스 준비 중이에요. 아직 모임 정보를 불러올 수 없어요." 가짜 데이터 없음 |
| 모집 중 / 최소 인원 미달 | "3자리 남음" / "최소 4명 · 현재 2명" |

| 이용 제한 / 탈퇴 요청 계정 | 상단 안내 띠 + 쓰기 버튼 비활성 |

## 8. 접근성 구현 요구

- 모든 상호작용 요소 키보드 접근, `:focus-visible` 링, 논리적 탭 순서. 날짜 스트립·칩은 `aria-pressed` 버튼 그룹(`role="group"` + 라벨).
- 건너뛰기 링크 "본문 바로가기": 레이아웃 맨 앞, 포커스할 때만 보임(`sr-only` → 포커스 시 좌상단 ink 상자), Enter로 `main#main-content`에 포커스(Phase 1 구현, Phase 5 E2E로 확인).
- 버튼·링크의 접근 가능한 이름은 **보이는 글자를 포함**한다(WCAG 2.5.3). 보충 설명은 `aria-label`로 덮지 말고 보이는 글자 뒤에 `VisuallyHidden`으로 붙인다(예: 날짜 칸 "수 11.25, 11월 25일 수요일, 오늘", 날짜 해제 칩 "날짜: 01.05 (1월 5일 토요일) 필터 해제" — Phase 5에 aria-label에서 바꿈, 화면 표시는 그대로). `VisuallyHidden`을 가로 스크롤 영역 안에 넣을 때는 감싸는 요소를 `relative`로 둔다(절대 위치 요소가 스크롤 영역 밖으로 빠져 문서에 가로 넘침을 만든다).
- 같은 사이트의 새 탭 링크(최초 설정의 약관·방침 보기)에는 스크린리더용 "(새 창에서 열림)"을 붙인다.
- 모든 내용은 랜드마크 안에 둔다: 상단 안내 띠(개발용 예시 데이터·계정 상태)는 이름 붙은 `<aside>`("개발 환경 안내"·"계정 상태 안내", 안쪽 `role="note"`). 제목 단계는 건너뛰지 않는다 — 목록 위에 h2가 없는 화면(내 모임)은 행 제목을 h2로(`MeetingRow headingLevel`), 관리자 탭 안 폼 제목은 h2. 태그만 바꾸고 className은 그대로(Phase 5 검수, axe `region`·`heading-order`).
- 다이얼로그: `role="dialog" aria-modal="true" aria-labelledby`, 포커스 트랩, ESC, 포커스 복귀.
- 페이지 이동 시 `<title>` 갱신과 본문 제목으로 포커스 이동(또는 건너뛰기 링크).
- 200% 확대·320px에서 정보 잘림 없이 재배치. 고정 rem 폭(예: 스켈레톤 막대 `w-32`)에는 `max-w-full`을 함께 둔다. 점검 방법과 결과는 [TEST_PLAN §3](./TEST_PLAN.md#3-뷰포트접근성-점검표).
- 준수 여부는 점검 결과로만 기록하고 "접근성 준수"라고 단정하지 않는다.
