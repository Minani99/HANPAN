# HANPAN(한판) 제품 요구사항 (PRD)

상태: 초안 (2026-11-23)

관련 문서: [ARCHITECTURE](./ARCHITECTURE.md) · [DB_SCHEMA](./DB_SCHEMA.md) · [UI_SPEC](./UI_SPEC.md) · [SECURITY](./SECURITY.md) · [TEST_PLAN](./TEST_PLAN.md) · [OPERATIONS](./OPERATIONS.md) · [ROADMAP](./ROADMAP.md) · [BACKLOG](./BACKLOG.md)

## 1. 개요

- 가칭 **HANPAN / 한판**. 대전광역시 보드게임 모임을 찾고, 신청하고, 열고, 참석을 관리하는 웹서비스.
- `BLOCKED:` 최종 브랜드명·상표·도메인은 정해지지 않았다(운영자 결정 필요). 워드마크 `HANPAN.`은 임시 텍스트 로고로 쓴다.
- 핵심 가치: **언제·어디서·무슨 게임을·몇 명이 하는지 빠르게 파악하고, 채팅 없이 참가 신청과 확정을 마친다.**
- MVP 우선순위: 모임 탐색 → 상세 확인 → 참가 신청 / 모임 개설 → 참석 관리.

## 2. 해결할 문제

| 문제 | MVP의 대응 |
|---|---|
| 모집 글이 카카오톡·당근·소모임 등에 흩어져 있다 | 대전 모임만 날짜·권역·장르로 모아 보여준다 |
| 취향·날짜·지역으로 찾기 어렵다 | 날짜 스트립, 장르 칩, 권역 선택, 검색을 URL 쿼리로 공유 가능하게 제공 |
| 인원 관리와 노쇼 | 정원·승인 방식·대기 신청·출석 체크를 서버 규칙으로 처리 |
| 장소 탐색이 불편하다 | 관리자가 확인한 공간 목록과 공식 외부 링크만 제공(예약·결제 없음) |

## 3. 사용자 역할

| 역할 | 설명 | 로그인 |
|---|---|---|
| 방문자 | 모임 목록·상세·공간 정보·정책 문서 조회 | 불필요 |
| 참가자(게스트) | 참가 신청·취소, 내 모임 확인, 신고 | 필요 |
| 모임장(호스트) | 모임 개설·수정·모집 마감·취소, 신청 승인·거절, 출석 체크 | 필요 |
| 관리자 | 신고 처리, 모임 숨김, 계정 제한, 공간·카테고리 관리 | 필요 + DB에 별도 부여된 관리자 역할 |

- 실명 공개 없음. 닉네임 + 소셜 계정 인증만 사용한다. 외부 본인확인을 하지 않으므로 "실명 인증"·"본인 확인" 배지를 표시하지 않는다.
- 공간 운영자(카페·파티룸) 계정은 MVP에 없다 → [BACKLOG](./BACKLOG.md).

## 4. MVP 범위

### 포함

1. 공개 탐색(`/`, `/meetings`): 날짜·장르·권역·검색어·모집 중 필터, 가까운 순/최근 등록순 정렬, 20개 단위 더 보기.
2. 모임 상세(`/meetings/:id`): 비로그인 공개, 상태별 참가 CTA, 공유, 신고.
3. 모임 생성·수정(`/meetings/new`, `/meetings/:id/edit`): 로그인 필수, 서버 재검증.
4. 내 모임(`/my/meetings`): 참가/주최 구분, 예정·대기·완료·취소 탭.
5. 참가자 관리(`/meetings/:id/participants`): 승인·거절, 대기자 확인, 출석 체크, 모임 취소.
6. 로그인·프로필(`/login`, `/auth/callback`, `/profile`): Google OAuth 기본, Kakao는 설정 완료 시에만 노출. 닉네임·선호 권역·관심 장르, 로그아웃, 탈퇴 요청.
7. 공간 정보(`/venues`, `/venues/:id`): 관리자 수동 등록 목록, 확인된 공식 링크만.
8. 신고·관리자(`/admin`): 신고 목록·상태 변경, 모임 숨김, 계정 제한, 공간·카테고리 관리.
9. 정책 문서(`/policies/terms|privacy|operations`): 운영자·법률 검토 전 초안임을 화면에 표시.

### 제외

추천 AI, 자동 매칭, 커뮤니티 게시판, 실시간 채팅, 제휴 예약·결제·정산, 본인확인, 구독, 이메일·푸시·알림톡 알림, 지도 API, **대기자 자동 승격**, 관심 알림 등록, 이미지 업로드 → 전체 목록과 사유는 [BACKLOG](./BACKLOG.md).

## 6. 핵심 규칙 요약

- 정원(`max_participants`)은 **모임장 1명을 포함한 전체 인원**이다. 모임을 만들면 모임장이 확정 참가자로 들어가고 화면의 "현재/전체"는 `confirmed_count/max_participants`다.
- 모집 상태는 DB에 `open`·`closed`·`cancelled`만 저장하고 "정원 마감·진행 중·종료"는 시간과 인원으로 계산한다.
- 모든 쓰기(모임·참가·신고·프로필)는 서버 RPC에서 권한·입력을 다시 검증한다. 버튼 비활성화는 보조 수단일 뿐이다.
- 알림 기능은 없다. 화면에서 "알림을 보냈어요"처럼 발송한 것처럼 표현하지 않는다.

## 8. 성공 지표(정의만, 목표치 없음)

출시 전이므로 목표 수치를 정하지 않는다. 별도 분석 도구는 도입하지 않고 DB 집계로 확인한다.

- 주간 개설 모임 수, 모임당 확정 인원, 신청→확정 전환 비율
- 출석 체크된 모임 중 `absent` 비율(노쇼 지표)
- 신고 접수·처리 건수와 처리 소요 시간

## 9. 가정과 제약

- 별도 백엔드 서버 없음. Supabase(Postgres·Auth·RLS·RPC)와 정적 프론트엔드만 쓴다.
- 이용자 전화번호·주민등록번호·신분증 정보는 수집하지 않는다.
- 공간 예약은 외부 공식 링크로만 안내한다.
- 홀덤은 비금전성 취미 모임만 허용한다.

- `BLOCKED:` 운영 이메일 주소(문의·이의제기·개인정보 요청 창구).
- `BLOCKED:` Supabase 프로젝트, Google/Kakao OAuth 설정, 배포 도메인 — 사용자 직접 수행 필요. [NEXT_STEPS](./NEXT_STEPS.md)
